# Module 1 Day 1: Data Detective

## Exercise purpose

The purpose of this exercise was to classify different examples of data by data type, structure and likely format or medium.

## My completed classification

| Data example | Classification | Structure | Likely format / medium |
|---|---|---|---|
| Restaurant transaction table | Mixed: contains quantitative measures (price, quantity), qualitative categories (menu item) and identifiers (order ID) | Structured | CSV, XLSX or database table |
| Customer review written online | Qualitative | Unstructured | Free text on a website, stored in a database or exported as text/JSON |
| JSON order response from a delivery application | Mixed: can hold quantitative, qualitative and identifier fields | Semi-structured | JSON |
| Menu price | Quantitative (a measurable value) | Structured (usually sits inside a table) | Field in a CSV, XLSX or database table |
| Photograph of a meal | Qualitative | Unstructured | Image file, e.g. JPEG or PNG |
| Restaurant branch name | Qualitative (category), can also act as an identifier-like label | Structured | Field in a CSV, XLSX or database table |
| Number of orders each day | Quantitative (a count) | Structured | CSV, XLSX or database table |
| Spreadsheet containing employee shifts | Mixed: qualitative (staff names, roles), quantitative (hours) and dates | Structured | XLSX or CSV |
| Audio recording of a customer-support call | Qualitative | Unstructured | Audio file, e.g. WAV or MP3 |
| Payment method | Qualitative (category, e.g. card or cash) | Structured | Field in transaction data (CSV or database table) |

**Key reminder:** a value made of digits is not automatically quantitative. An order ID labels a record rather than measuring anything. Structure is how data is organised; format is how data is stored or exchanged.

## What I learned

Embarking on my introduction to data science felt quite daunting at first. Although I work with data daily through data entry and review, what lay beyond that, and how data could truly be put to work, felt unfamiliar. 
This made joining the training essential to my professional development. From the outset, the course was eye-opening, as it bridged a real gap in my knowledge around the distinctions between quantitative, qualitative and identifier data: quantitative data is largely numerical, qualitative data is largely descriptive and word-based, and identifier data is a unique ID that labels one specific record, such as an order ID. 
I also learned about the different ways data can be structured: structured (tables), semi-structured (like JSON) and unstructured (like photos or audio). 
The most fascinating aspect, however, was understanding the differences between data roles: the data analyst (who uses data to answer business questions), the data scientist (who applies statistics and models to uncover patterns and make predictions) and the data engineer (who builds the systems that collect, store and prepare data). 
I had always assumed these were the same job under different titles, but understanding their distinct responsibilities brought data to life for me, revealing how data evolves and gains value as it moves through each role.
